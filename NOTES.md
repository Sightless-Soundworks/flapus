# Implementation notes

How the Opus encoder is generated and how the FLAC encoder searches, for whoever changes
the code.

## Source map (`src/`, in amalgamation order)

| File | Content |
|------|---------|
| `api.h` | public API, error codes, encoder availability check |
| `common.c` | helpers, range decoder |
| `math.c` | log, log10, exp, pow, sin, cos, acos from fdlibm (the same results everywhere) |
| `tables_celt.c`, `tables_silk.c` | decoder tables (`tools/gen_tables.py`) |
| `celt_common.c`, `celt_dsp.c`, `celt_dec.c` | CELT: modes, FFT/MDCT, bands, decoder |
| `silk_common.c`, `silk_dec.c` | SILK shared code and decoder |
| `opus_dec.c` | Opus packet parsing, mode glue, multistream decoder |
| `io.c` | buffered input (files, stdin, memory, callbacks), output streams, stream format, source and sink interfaces, tags, MD5, base64, WAV input and output |
| `file_dec.c` | streaming Ogg reader, Opus file decoding (two passes), resampler, dither |
| `flac_dec.c` | FLAC decoder: native and Ogg FLAC sources with seeking, metadata, CRCs, MD5 check, frame decoder API |
| `flac_enc.c` | FLAC encoder: search, block size DP, threads, verification, metadata |
| `enc_libopus.c` | the libopus 1.6.1 float encoder, generated by `tools/gen_opus_enc.py` |
| `enc_front.c` | opusenc/libopusenc: setup, downmix, resampling, LPC extension, Ogg writer, Opus output sink, packet encoder API |
| `convert.c` | format detection, conversion, in-memory audio, `fl_reader`/`fl_writer` |

`enc_libopus.c` and `enc_front.c` are wrapped in `#ifdef FLAPUS_HAVE_ENCODER`.

## Conversion pipeline

A source (`fl_source` in `io.c`) is opened on the input and then decodes step by step
(a block, a frame or an Ogg page per step), passing interleaved `int` samples (WAV/FLAC
channel order, right-justified to `bits`) to a sink, see `fl_format` and `fl_sink`.
Conversion runs the steps to the end; `fl_reader` runs them as far as needed and keeps
the samples in a queue.

- **Sources**: `fl_wav_open`, `fl_flac_open` (native and Ogg) and `fl_opus_open` (16-bit
  at the original rate by default, dither).
- **Seeking**: WAV by position; FLAC by bisection over the frames (frame headers carry
  the sample number); Ogg FLAC by reading from the start; Opus with marks collected in
  the first pass (granule and offset of every page that ends a packet group), restarting
  80 ms early with a new decoder and a resampler that starts on a whole output sample.
- **Sinks**: WAV, FLAC and Opus, plus a memory sink for `fl_read_audio`.

The Opus sink handles every source the same way:

- It reads in chunks of 960 samples and reorders WAV to Vorbis channel order for 3 and
  5-8 channels.
- It applies the optional downmix and converts with the exact scale `v * 2^(1-bits)`.
- It sets the LSB depth from the source sample size (`container_bits`).

FLAC sources give the same floats as WAV sources. Their ReplayGain tags become header
gain:

- `REPLAYGAIN_ALBUM_GAIN` becomes the OpusHead gain at the R128 level:
  `256*(album+84-reference_loudness)+0.5`, floored and clamped.
- `REPLAYGAIN_TRACK_GAIN` becomes `R128_TRACK_GAIN`.

## Opus decoder

The decoder is plain float C. It uses the operation order of libopus's SSE/AVX2 code
paths (inner products in 4 lanes, etc.).

File-level handling, from opusfile and opus-tools:

- **opusfile**: pre-skip, end trimming from the granule position, link handling, gain.
  A first audio page that is also the last page, and holds more audio than its granule
  position, starts at 0 and trims the end.
- **opusdec**: Speex resampler quality 5 to the original rate, soft clip, shaped dither
  with seed 22222, WAV channel order.

## Opus encoder

`src/enc_libopus.c` is libopus 1.6.1's encoder, not a rewrite of it.
`tools/gen_opus_enc.py` makes it from the libopus sources:

- The `#if` blocks are resolved for a plain C float build: `alloca` for temporary
  arrays, no intrinsics, no run-time CPU detection, no `FLOAT_APPROX`. A macro that the
  sources test but never define is a build option and counts as undefined; names with a
  leading underscore come from the compiler and stay.
- The files are joined like a preprocessor would: the `.c` files in libopus's order,
  each header in place where it is first included. A file that defines data another
  file uses comes first.
- Every file-scope name gets the prefix `oe_` and becomes `static`; `extern` data
  declarations go. A macro that two headers define differently (`PI`) gets one name per
  header, and each file uses the one it would have seen.
- Whatever the four multistream entry points do not reach is left out.
- `log`, `log10`, `exp`, `pow`, `sin`, `cos` and `acos` become the `fl_` functions of
  `src/math.c`.

`src/enc_front.c` sets the encoder up as opusenc from the current opus-tools (git) does:
the same ctl calls in the same order, 750 kbit/s per channel at most. It does
libopusenc's work: 20 ms reads, the Speex resampler (quality 5, full sinc table, `sin`
from `src/math.c`, the summation order of its SSE inner product), the LPC extension at
the end, the last frame size, and the Ogg pages. Downmix and ReplayGain follow opusenc in
float and double, as written there.

To update libopus: run the generator on the new sources, rebuild the reference opusenc
with `tools/build_ref_opusenc.sh`, and run `test/grid.sh`.

## FLAC encoder

The goal is the smallest valid FLAC file. The decoder in `flac_dec.c` decodes every
frame again before it is written, and any mismatch aborts with `FL_ERR_INTERNAL`.

### Per subframe (`fl_search_subframe`)

Candidates:

- constant, verbatim, wasted bits, and fixed predictors of order 0-4;
- LPC from windowed autocorrelation and Levinson-Durbin. Level 0 uses tukey(0.5); the
  other levels use the windows of flac's subdivide_tukey(N) (N = 2-5): tukey(0.5/N) over
  the block, each half, and for each d = 3..N each d-th of the block with the same tapers,
  plus the block without that d-th. As in libFLAC, "without" costs nothing: its
  autocorrelation is the whole block's minus the part's. So the 17 windows of N = 4 cost
  about four autocorrelations of the block. Each window gives the order (or the 3 orders)
  with the lowest estimate from the prediction error;
- LPC from the covariance method (exact least squares; all orders are solved from one
  matrix built with the shift recursion).

Refinements, applied to the best candidate:

- **Precision search**: all coefficient precisions within libFLAC's 32-bit decoding
  rule `prec <= 32-bps-log2(order)` for 17 bits or less. Quantization uses libFLAC's
  error feedback. The default precision is libFLAC's: by block size, and 13-15 above
  17 bits.
- **IRLS**: the weights are `1/(|e|*mean|e| of the neighbourhood)`. For Laplacian
  residuals within Rice partitions this approximates minimizing the Rice cost.
- **Hill climb**: ±1 on each quantized coefficient, evaluated incrementally (O(n) per
  try).

Residual coding:

- Candidates are compared with a fast Rice estimate: partition sums with a correction
  for the floor; escapes included.
- The winner gets the exact plan: every partition order, the exact parameter per
  partition, Rice vs Rice2, and escape codes (including 0-bit escapes for silent
  partitions).

Arithmetic:

- Prediction sums use 32-bit math when `bps+prec+bitlen(order) <= 33` (the sum then
  fits in 32 bits), and double when it is at most 53 (exact integers, vectorizable).
- 64-bit math is used otherwise.
- Residuals that do not fit in 32 bits reject the candidate.

### Stereo

All four channel assignments are searched: left/right, left/side, side/right, mid/side
(levels 1-7: only the one the quick estimate picks, see below). With 32-bit audio the
side channel has 33 bits; the samples are kept in 32 bits, so blocks where the side does
not fit there are coded as left/right.

### Block sizes (`fl_flac_process`)

The input is processed in segments of 65536 samples. Within a segment, dynamic
programming over a grid of `unit` samples finds the cheapest sequence of blocks, which
gives a variable block size stream. Costing every block on the grid (all starts, all
lengths up to the maximum) was 99 % of the encoding time, so the search has two passes:

- First a sparse set: blocks of 2^a units from every 2^(a-1)-th unit, blocks of 3*2^a
  units from every 2^a-th unit, and the longest blocks. That is about 5 blocks per unit
  instead of 18, and the long ones, which cost the most, are the rarest.
- Then, with `refine` r, every block whose start and end both lie within r units of a
  boundary of the first result, and the dynamic programming once more.

With the quick estimate the size stayed within 0.01 % of the full set; with the light
search it grew by 0.07 %, and the search was 3 times faster.

The block cost is either:

- the quick estimate (levels 2-8): least-squares LPC (covariance method) from prefix
  sums of the autocorrelation products, one order, one quantization, plus the order 2
  fixed residual from prefix sums of its Rice values; or
- a light subframe search with estimated sizes (`--lax` and above 48 kHz),
  whose fixed residuals also come from prefix sums.

The quick estimate first used the autocorrelation method on the rectangular prefix sums.
Without a window, its coefficients were poor on music with a steep spectrum, and the
estimates were up to 30 % above the real sizes; least squares fixed most of that. It
also needs the wasted bits, or blocks with more wasted bits look as expensive as the
others. Above
48 kHz (orders up to 32) and with `--lax` (blocks up to 16384) it still misjudges blocks,
so those use the light search at every level.

Stereo with `one_mode` (levels 1-7): the quick estimate picks one of the four channel
assignments and only its two channels get the full search. The full search of all four
was half the time of a frame; the files grow by about 0.02 %.

Some measurements on the test corpus (190 s), in total size and one thread:

- Level 5: 0.04 % smaller than the previous level 5 (all blocks, light search, 3
  windows), 10 times faster. Level 8: 0.16 % smaller than the previous level 5, 2 times
  faster.
- The subdivide_tukey windows: 0.15-0.3 % smaller files than tukey(0.5) with
  partial_tukey(2), at about the same time.
- With these windows the light search no longer beats the quick estimate.
- Variable block sizes save about 0.4-1 % against fixed 4096.
- IRLS gives most of what the coefficient refinements give (about 0.1 %); the hill climb
  adds little after it.
- Above 48 kHz the grid is max_block/8 (levels 0-6) or max_block/16 (7-8), 1024 or 2048
  samples in the subset. Blocks there are short in time, so the coarse grid costs
  nothing measurable and makes the search 5-8 times faster.

Speed and output:

- The fixed residuals of each source (left, right, side, mid or channel) are computed
  once per segment, and the block searches read slices of them. Blocks with wasted bits
  compute their own.
- Where only the comparison with the best candidate matters, a Rice estimate stops as
  soon as it cannot win.
- With SSE2, the 32-bit prediction sums use `pmaddwd` on 16-bit parts of the samples,
  and the residuals, the autocorrelation and the Rice sums have SSE2 versions as well.
  They give the same results as the plain C code, so the output does not depend on SSE2.
- With `threads` above 1, block costs and frames are computed in parallel (static
  interleaving, per-thread work spaces). The output does not depend on the thread
  count. The library default is one thread; the command line tool uses one per CPU.
- Subset limits apply unless `--lax`: up to 48 kHz, order ≤ 12, partition order ≤ 8
  and blocks ≤ 4608. Above 48 kHz, blocks ≤ 16384.
- `--lax` allows order 32 and blocks up to 16384 (32768 above 48 kHz). That gives
  another 2-5 %, mostly from the higher LPC order.

### File layout

- Metadata blocks: STREAMINFO (patched at the end with sizes, total and MD5), SEEKTABLE,
  VORBIS_COMMENT if there are tags, PICTURE, kept APPLICATION/CUESHEET blocks, PADDING.
- The seek table needs the length in advance and a seekable output. It has one
  placeholder per 10 s; when a frame is written that holds the next target, it becomes a
  seek point. Targets that fall into an earlier point's frame stay placeholders.
- Frame headers use the sample number (variable blocking) and explicit rate and bit
  depth codes (subset).

## Regenerating generated sources

- `python tools/amalgamate.py` rebuilds `flapus.h` from `src/`, with `LICENSE` at the end.
- `python tools/gen_opus_enc.py <libopus 1.6.1 dir>` writes `src/enc_libopus.c`.
- `python tools/unifdef.py <libopus dir> <out dir>` resolves the `#if` blocks for the
  decoder's view, and `python tools/gen_tables.py <out dir> src` writes the table files.
