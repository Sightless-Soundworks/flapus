# Implementation notes

How the Opus bit-exactness is achieved and how the FLAC encoder searches, for whoever
changes the code.

## Conversion pipeline

Every source pushes interleaved `int` samples (WAV/FLAC channel order, right-justified to
`bits`) into a sink, see `fl_format` and `fl_sink` in `io.c`.

- **Sources**: `fl_run_wav`, `fl_run_flac` (native and Ogg) and `fl_run_opus` (opusdec
  output: 16-bit, original rate, dither).
- **Sinks**: WAV, FLAC and Opus, plus a memory sink for `fl_read_audio`.

The Opus sink reproduces opusenc's input handling for every source:

- It reads in chunks of 960 samples and reorders WAV to Vorbis channel order for 3 and
  5-8 channels.
- It applies the optional downmix and converts with the exact scale `v * 2^(1-bits)`.
- It sets the LSB depth from the source sample size (`container_bits`).

opusenc's FLAC reader produces the same floats as its WAV reader. For FLAC sources it
also turns ReplayGain tags into header gain, and flapus does the same:

- `REPLAYGAIN_ALBUM_GAIN` becomes the OpusHead gain at the R128 level:
  `256*(album+84-reference_loudness)+0.5`, floored and clamped.
- `REPLAYGAIN_TRACK_GAIN` becomes `R128_TRACK_GAIN`.

## Opus decoder

The reference decodes come from a 64-bit opusdec, so the decoder is plain float C. It
uses the operation order of the SSE/AVX2 code paths libopus selected (inner products in 4
lanes, etc.).

File-level behaviour follows opusfile and opusdec:

- **opusfile**: pre-skip, end trimming from the granule position, link handling, gain.
  A first audio page that is also the last page, and holds more audio than its granule
  position, starts at 0 and trims the end.
- **opusdec**: Speex resampler quality 5 to the original rate, soft clip, shaped dither
  with seed 22222, WAV channel order.

## Opus encoder: x87 emulation

The reference opusenc is a 32-bit x87 build (libopus 1.6.1, FLOAT_APPROX, SSE presumed,
AVX2 via RTCD for `pitch_xcorr` and the SILK inner product). x87 keeps values in 80-bit
registers and rounds only when it stores them. The port mirrors this:

- Values the compiled reference holds in registers are `xf` (`long double`). They are
  rounded to `float`/`double` exactly where the reference stores them: array and struct
  writes, register spills, call arguments, and float-to-int conversions (a float store
  followed by `cvttss2si`). Return values stay extended.
- Every function was checked against the disassembly of the reference objects to find
  the spills. Comments in the code mark the non-obvious ones.
- `fl_x87_enter()` sets 64-bit precision (the MinGW x64 default is 53-bit). Every entry
  point that does `xf` arithmetic must run inside it; the Opus sink enters it for each
  call.
- libm functions are reproduced as MinGW i686 implements them:
  - `sqrt` is `fsqrt`.
  - `log`/`log2l` use `fyl2xp1` near 1 and `fyl2x` otherwise.
  - `exp2l` uses `frndint`+`f2xm1`+`fscale`.
  - `pow` for non-integer exponents is `exp2l(y*log2l(x))`.
- SSE/AVX2 kernels (inner products, `op_pvq_search_sse2` with `rcp`/`rsqrt`) are
  emulated lane by lane, with the scalar tails done in x87.

### Subtle points found while matching

- `dc_reject`: the coefficient `6.3f*3` is folded in float (`18.900001525878906f`).
- Hybrid high-band gain: `SHR32` is a no-op in the float build.
- 10 ms mono-from-stereo: the MDCT input is the `(float)(.5*a+.5*b)` downmix.
- CELT `OPUS_SET_BITRATE` ignores values of 500 or less. This happens in surround
  hybrid streams when the SILK masking boost exceeds the stream rate.
- opusenc applies no 256 kbit/s per channel clamp, only libopus's 750 kbit/s per
  channel. `--bitrate 1000` is 1 Mbit/s.
- opusenc reorders 3- and 5..8-channel input to Vorbis order before downmixing or
  encoding. The downmix sums in extended precision with one final store.
- Surround analysis: `logSum` rounds `2*diff` to float before `floorf`. The channel
  offset and all masking sums in CELT and SILK stay in registers.

## FLAC encoder

The goal is the smallest valid FLAC file. The decoder in `flac_dec.c` decodes every
frame again before it is written, and any mismatch aborts with `FL_ERR_INTERNAL`.

### Per subframe (`fl_search_subframe`)

Candidates:

- constant, verbatim, wasted bits, and fixed predictors of order 0-4;
- LPC from windowed autocorrelation and Levinson-Durbin, using libFLAC's tukey(0.5),
  partial_tukey(2) and punchout_tukey(3) shapes, plus welch and other tukeys;
- LPC from the covariance method (exact least squares; all orders are solved from one
  matrix built with the shift recursion).

Refinements, applied to the best candidate:

- **Precision search**: all coefficient precisions within libFLAC's 32-bit decoding
  rule `prec <= 32-bps-log2(order)` for 17 bits or less. Quantization uses libFLAC's
  error feedback.
- **IRLS**: the weights are `1/(|e|*mean|e| of the neighbourhood)`. For Laplacian
  residuals within Rice partitions this approximates minimizing the Rice cost.
- **Hill climb**: ±1 on each quantized coefficient, evaluated incrementally (O(n) per
  try).

Residual coding:

- Candidates are compared with a fast Rice estimate: partition sums with a correction
  for the floor; escapes included.
- The winner gets the exact plan: every partition order, the exact parameter per
  partition, Rice vs Rice2, and escape codes (including 0-bit escapes for silent
  partitions).

Arithmetic:

- Prediction sums use 32-bit math when `bps+prec+log2(order) <= 32`, and double when
  it is at most 53 (exact integers, vectorizable).
- 64-bit math is used otherwise.
- Residuals that do not fit in 32 bits reject the candidate.

### Stereo

All four channel assignments are searched: left/right, left/side, side/right,
mid/side.

### Block sizes (`fl_flac_process`)

The input is processed in segments of 65536 samples. Within a segment, dynamic
programming over a grid of `unit` samples finds the cheapest sequence of blocks, which
gives a variable block size stream. The block cost is either:

- level 3: rectangular autocorrelation from prefix sums plus one LPC trial; or
- levels 4-8: a light subframe search with estimated sizes.

Some measurements on the test corpus, in total size:

- The light search costs about 0.25 % less than the quick estimate.
- Variable block sizes save about 0.4-0.7 % against fixed 4096.
- A finer grid (128 instead of 256) saves about 0.03 %.

Speed and output:

- With `threads` above 1, block costs and frames are computed in parallel (static
  interleaving, per-thread work spaces). The output does not depend on the thread
  count. The default is one thread.
- Subset limits apply unless `--lax`: up to 48 kHz, order ≤ 12, partition order ≤ 8
  and blocks ≤ 4608. Above 48 kHz, blocks ≤ 16384.
- `--lax` allows order 32 and blocks up to 16384 (32768 above 48 kHz). That gives
  another 2-5 %, mostly from the higher LPC order.

### File layout

- Metadata blocks: STREAMINFO (patched at the end with sizes, total and MD5), then
  VORBIS_COMMENT if there are tags, then PICTURE, then kept APPLICATION/CUESHEET blocks.
- No padding and no seek table.
- Frame headers use the sample number (variable blocking) and explicit rate and bit
  depth codes (subset).

## Regenerating generated sources

- `python tools/amalgamate.py` rebuilds `flapus.h`.
- Both generators below read a libopus 1.6.1 tree whose `#if` blocks were resolved with
  `python tools/unifdef.py <dec64|enc32> <libopus dir> <out dir>`.
- `python tools/gen_tables.py <flattened dir> src` writes the table files.
- `OPUS_FLAT=<flattened dir> python tools/gen_silk_enc.py silk_encode_frame_FLP silk_encode_do_VAD_FLP`
  rewrites `src/enc_silk_fix.c` from `tools/silk_enc_prelude.c`, `tools/silk_enc_protos.c`
  and the fixed-point SILK sources.
